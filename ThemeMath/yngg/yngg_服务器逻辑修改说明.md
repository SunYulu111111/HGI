# yngg 服务器规则与本地实现对齐说明

更新日期：2026-10-26。TYPE 0 使用 NORMAL / SP 混合轴，并通过初始有奖/无奖 Bonus 概率区分实际玩法入口与图标展示。每次 Base 从空金色区域开始，只有本次 Base 有实际消除且终盘有 Bonus 时才触发。当前 `special/yngg_game_server.conf` 的 `[Game Info]` 版本为 104。

## 共享翻牌规则

服务器与本地均应从 `[Game Info]` 读取以下 PascalCase 字段；TYPE 0、4、8、12、17 的 Base、普通 Free、Super Free 共用，不允许数字 TYPE 节或 Bonus `[Type0]` 覆盖：

| 字段 | 当前值 | 计数范围 |
| --- | ---: | --- |
| `BonusMaxPotCount` | 5 | 单次金色玩法及其全部重翻累计生成的 Pot |
| `BonusMaxCloverCount` | 3 | 单次金色玩法及其全部重翻累计生成的 Clover |
| `BonusRevealMinCoinCount` | 1 | 每批新翻 symbols 中的 coin 最少数 |

`BonusMaxPotCount` 缺失时使用旧字段 `bonus_max_round`，两者都缺失时默认 5；显式新字段优先。四叶草与 coin 字段缺失时分别默认 3 和 1。三项限制均为非负整数。旧字段保留作兼容，不再将其理解为重翻轮数。

每次金色玩法开始时将 Pot、Clover 累计数清零，跨该次玩法的全部重翻累计；被后续翻牌覆盖的四叶草仍计数。玩法结束后计数重置。Super Free 保留金色位置，但下次独立 Bonus 触发重新计数，不沿用整个 Free session 的累计数。保留 Pot 不重复计数，且不算 coin。

首次翻牌以全部金色位置为一批；Pot 结算后，以需要重翻的非 Pot 位置为新一批。每批 coin 计数从 0 开始，按 `(Row 升序, Col 升序)` 逐格扫描：

1. 先依据本次玩法累计数屏蔽已达上限的 Pot、Clover 类型。
2. 剩余未翻格数包含当前格；等于仍需补足的 coin 数时，直接生成 coin，仅按当前 TYPE 的金币档位权重抽取奖值，跳过类型随机抽取。
3. 否则按允许类型的原相对权重抽取，再按类型抽对应档位。配置最少 coin 数大于 0、且允许类型权重全部归零时，同样直接抽 coin 档位。
4. 每生成一格立即更新本批 coin 数与整次玩法 Pot/Clover 累计数，下一格立即使用更新后的限制。

不能先生成整批后删除超额 Pot/Clover，也不能靠整批重抽实现 coin 保底。待翻位置少于配置所需 coin 数时视为无效。外部 `golden_rounds` 同样校验累计上限及每批新 coin 最少数；既有接口支持的部分位置回放可以保留，但所提供批次仍需满足限制。

## 结算顺序与保留内容

四叶草先结算；聚宝盆按列升序、行下标降序逐个收集，展平顺序与 `g_iPotScan=4,3,2,1,0,9,8,7,6,5,...` 一致。后结算的盆会收集先结算盆的金额；盆保留，其他金框重翻。JP 揭示即累加，跨重翻保留，不参与四叶草放大和聚宝盆收集。翻牌、四叶草及输出 `cells` 的顺序继续为 `(Row, Col)` 升序。

金币保留 0.2/0.5/1/2/3/4/5/10/15/20/25/50/100/250/500，四叶草保留 2/3/4/5/10/20，JP 保留 MINI 10x、MINOR 25x、MAJOR 100x、GRAND 5000x。普通免费、超级免费均保留初始 10 次；2/3 个 Scatter 追加 2/4 次。上述新增生成限制会改变奖励分布与随机流，不能视为纯性能优化。

本地 Feature 先累计倍率，最后乘下注并 round；此前服务器逐币金额截断在小额下注时可能不同。对齐测试应继续覆盖金额单位和舍入顺序。

## 已有 TYPE 0 独立 Bonus 权重

`special/yngg_bonus.conf` 的 `[Type0]` 只允许以下四个权重字段；奖值数组仍从 `[GENERAL]` 读取：

| TYPE 0 字段 | GENERAL 继承字段 |
| --- | --- |
| `BonusSymbolTypeProbability` | `BONUS_SYMBOL_TYPE_PROBABILITY` |
| `BonusCoinMultipleProbability` | `BONUS_COIN_MULTIPLE_PROBABILITY` |
| `BonusCloverMultipleProbability` | `BONUS_CLOVER_MULTIPLE_PROBABILITY` |
| `BonusJpTypeProbability` | `BONUS_JP_TYPE_PROBABILITY` |

先校验 GENERAL，再解析 Type0 覆盖；TYPE 0 的 Base、普通 Free、Super Free 使用有效覆盖，TYPE 4/8/12/17 使用 GENERAL。缺少 Type0 节或某项覆盖时继承 GENERAL；旧数字节不参与读取。切换 TYPE 必须重选有效权重。数组长度必须与档位匹配，不允许负权重、全零、显式空数组或未知 Type0 字段；加载失败不能污染已生效配置。类型下标固定为 coin、clover、pot、jackpot。

当前 TYPE 0 类型权重为 `10081,40,6,5`。金币 0.2/0.5/1 各占金币档位抽样的 16.2%，2/3/4/5 分别为 25.3845%/14.5%/7%/3%；100/250/500 各为 0.0185%，金币条件均值 1.99034x。四叶草档位权重仍为 `23,23,23,23,4,4`，JP 档位仍为 `80,25,8,1`；三种模式共用同一组 TYPE 0 奖励参数。

此前审核的 `/Users/sunyulu/Downloads/server_ynggtool` 不读取 Type0 覆盖，不能直接得到本地相同分布。对接服务器除同步 Type0 读取、切换与校验外，还需实现本次共享累计上限与 coin 保底后重新编译验证，并核对实际生效数组和共享限制。

## Base 入口配置

TYPE 0 Base 使用 `BASE_RATE=8580,1420,0,0`，按 85.8% / 14.2% 选择 `NORMAL_ROLL` / `SP_ROLL`，选定的轴贯穿本次全部消除补牌。FIX、ZERO 的抽取权重均为 0，预设内容保留。Base Bonus 入口由初始特殊图标权重控制：有奖盘通过 `BaseWinBonusCountProbability` 校准实际触发率；无奖盘通过 `BaseNoWinBonusCountProbability` 展示 Bonus。

初盘无奖的 `BaseNoWinBonusCountProbability=98,2` 仅决定满足放置条件时是否展示 Bonus；无本次消除就没有金色区域，不能触发。初盘有奖的 `BaseWinBonusCountProbability=9581,419` 表示合格有奖初盘的条件放置概率为 4.19%，按实际付费 Base 触发率约 1.25% 校准。两组权重下标均为 0 / 1 个 Bonus，只在实际放入不超过 2 个 Scatter 且仍有候选时抽取。掉落替换权重为 `999,1,0`，Base 不通过掉落生成新的 Bonus。

TYPE 0 Scatter 数量权重为 `10000,1000,500,77`，Super 转化概率为 `880/10000`；Free 有金框/无金框的 Bonus 数量权重为 `57,43` / `97,3`。主 TYPE 0 轴版本为 104，免费轴为 103，服务器玩法配置为 104。Free 末局终盘保底不变。

Python 仿真不执行服务器 GROUP 选择和砍分，默认最多 100 轮消除。此前服务器的 50 轮默认和 GROUP 砍分会改变结果；FreeCut 调用链按单次 Free Spin 比较、注释却写整轮 Free 的范围差异仍需对接时核实。

## 2026-10-26 Bonus 奖励校准

TYPE 0 的 Base、普通 Free、Super Free 共用当前 `[Type0]` 奖励权重；当前方案的 Base Bonus RTP 目标为 20%，不将历史普通 Free Bonus 18%、Super Free Bonus 4% 或总 RTP 95% 当作仍然满足的约束。主轴、免费轴、入口权重、奖值档位及翻牌规则保持原参数，其他 TYPE 使用的 `[GENERAL]` 未参与本项奖励调整。

完整随机抽样使用 4 个独立种子 `20261026321`–`20261026324`，每个种子 2,500 万局付费 Base，并执行全部触发的免费游戏，共 1 亿局。所有 RTP 的分母为付费 Base 累计下注：

| --- | ---: |
| Base 消除 | 39.9608% |
| Base Bonus | 20.0337% |
| 普通 Free 消除 | 9.0527% |
| 普通 Free Bonus | 53.3718% |
| Super Free 消除 | 0.8842% |
| Super Free Bonus | 11.5945% |
| 总 RTP | 134.8976% |

Base Bonus RTP 标准误为 0.04527 个百分点，总 RTP 标准误为 0.13864 个百分点。样本中 Base Bonus 触发率为 1.251033%，触发后的条件均值为 16.0137x；付费流程子样本中的条件标准差为 37.2185x。普通 / 超级免费触发率分别为 0.617314% / 0.060618%。共享奖励分布同步提高了免费 Bonus 的贡献，总 RTP 134.8976% 是这组参数的完整流程结果，不应标记为历史总 95% 方案。

条件期望校验另使用独立种子 `20261026331`–`20261026334`，每个种子 1,250 万局，共 5,000 万局。该模式积分独立奖励档位、保留类型和几何路径随机性，得到 Base Bonus RTP 20.0738%（标准误 0.02953 个百分点）、普通 Free Bonus 53.4053%、Super Free Bonus 11.4447%、总 RTP 134.7974%。两批属于不同估计方式，不合并其分位数或把条件期望模式作为实付波动样本。

当前本地原生采样器已将 20,000 局、280,477 次随机请求逐调用回放到实际 Python，六项奖金和触发标记一致，其中 234 次 Base Bonus。统计结果、源文件与配置指纹见 `bonus_type_calibration.json`；没有运行此前提供的 Linux 服务器二进制。波动降低的前后比较采用下节相同经验金格分布与等量 Feature 样本，不直接把不同付费流程子样本的条件标准差相减。

## Bonus 波动与尾部对照

从 1,000 万局付费 Base 抽取 125,130 个实际触发的金格布局，在相同经验布局分布下，对奖励调整前后各独立抽取 2,000 万次完整金色玩法，种子为 `20261026251`。这些统计以一次触发后的整轮 Bonus 倍率为样本，未把免费游戏中的 Bonus 混入 Base 对照：

| 指标 | 奖励调整前 | 当前奖励分布 |
| --- | ---: | ---: |
| 条件均值 | 6.4332x | 16.0187x |
| 绝对标准差 | 42.6206x | 39.7261x |
| 变异系数（标准差 / 均值） | 6.6251 | 2.4800 |
| P50 | 3.7x | 11.7x |
| P90 | 8.5x | 26.5x |
| P99 | 26.7x | 59.9x |
| 低于 5x 的比例 | 67.6614% | 5.3612% |
| ≥5000x 次数 / 样本数 | 702 / 20,000,000 | 669 / 20,000,000 |
| ≥5000x 频率 | 0.00351% | 0.003345% |

绝对标准差与变异系数均降低，常见回报向中档移动。整轮 ≥5000x 的样本频率差处于采样误差范围内；这说明大奖机会仍然存在，不能据此声称整轮大奖概率完全相同。金币 100/250/500 各 0.0185% 是金币档位的条件概率，JP `5/10132` 是未受强制金币及上限干预时的名义类型概率，也不能直接当作整轮大奖频率。

另以 1,000 万次类型/重翻路径积分奖励档位的一阶、二阶矩，保留共享四叶草乘子与聚宝盆收集的相关性，得到绝对标准差约 45.7291x → 40.4802x、变异系数约 7.1172 → 2.5272，下降方向一致。完整随机样本的标准差会受极少数长尾结果影响；该积分减少档位噪声，仍含类型路径采样误差，也受经验金格分布样本的限制。正式完整流程 RTP 与文件指纹见 `bonus_type_calibration.json`。

## 对接检查

1. 核对 0→4→8→12→17→0 切换时 Bonus 权重对应正确，三项共享限制始终相同。
2. 首次翻牌与多次重翻都检查单次玩法 Pot≤5、Clover≤3，每批新 coin≥1；接近上限时下一格立即屏蔽对应类型。
3. 验证一格翻牌必为 coin；保留 Pot 不能代替新 coin；允许类型权重归零时仍按 coin 档位生成。
4. 外部回放应拒绝超限或缺 coin 的批次；独立 Bonus 触发重置累计数，Super Free 只保留金格，不保留累计限制计数。
5. 验证四叶草、聚宝盆扫描顺序、JP 累积与金额舍入；免费次数和重触发规则保持原值。
6. `source_math.json` 记录当前规则和有效权重，通过 `CurrentCalibrationReport` 引用当前校准，并以 `HistoricalFullTargetsNotRetuned` 区分没有重新追平的历史全量目标；旧采样及性能报告仅供历史核对。
